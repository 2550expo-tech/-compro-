ฐานข้อมูลคืออะไร

ฐานข้อมูล (database) คือที่เก็บข้อมูลแบบมีระเบียบ คิดว่าเป็น สมุด Excel บนคลาวด์ ที่มีหลายชีต แต่ละชีตเรียกว่า ตาราง (table) แต่ละแถวคือข้อมูล 1 ชิ้น (row) แต่ละคอลัมน์คือช่องข้อมูล (column) เช่น ตาราง transactions มี 1 แถวต่อรายการเงิน 1 รายการ

iduser_idkindamount_satangtitlestatusoccurred_at
a1b2…มิ้นท์expense8500ข้าวมันไก่confirmed2026-10-08T05:10Z
c3d4…มิ้นท์income1000000ค่าขนมจากที่บ้านconfirmed2026-10-01T02:00Z
e5f6…ต้นexpense125000โอนให้ นาย ส***draft2026-10-07T11:42Z

ตัวอย่างสมมติ คอลัมน์ user_id จริงเป็นรหัสยาว (UUID) ไม่ใช่ชื่อ

ภาษาที่ใช้สั่งฐานข้อมูลคือ SQL คำสั่งพื้นฐานมี 4 คำ

SQLความหมายในแอปเขียนว่า (supabase-js)
SELECT * FROM transactionsอ่านข้อมูลdb.from('transactions').select('*')
INSERT INTO transactions …เพิ่มแถวdb.from('transactions').insert(row)
UPDATE transactions SET … WHERE id = …แก้แถวdb.from('transactions').update(row).eq('id', id)
DELETE FROM transactions WHERE id = …ลบแถวdb.from('transactions').delete().eq('id', id)

แอปไม่ได้เขียน SQL ตรง ๆ แต่ใช้ไลบรารี supabase-js ซึ่งแปลงคำสั่งเป็นคำขอผ่านอินเทอร์เน็ต แล้วเซิร์ฟเวอร์แปลงเป็น SQL ให้อีกที

Supabase ให้อะไรทีมเราบ้าง

ส่วนคืออะไรใช้ทำอะไรใน MindPay
PostgreSQLฐานข้อมูลแบบตาราง ที่นิยมที่สุดตัวหนึ่งของโลกเก็บ 4 ตาราง: profiles, transactions, savings_goals, ai_usage
Authระบบบัญชีผู้ใช้สำเร็จรูปสมัคร เข้าสู่ระบบ ส่งรหัส 6 หลักทางอีเมล ลืมรหัสผ่าน
REST API อัตโนมัติสร้าง "ประตู" ให้เข้าถึงตารางผ่านอินเทอร์เน็ตให้เองแอปอ่าน/เขียนตารางได้โดยไม่ต้องเขียนเซิร์ฟเวอร์เอง
Row Level Securityกฎความปลอดภัยรายแถวแต่ละคนเห็นเฉพาะแถวของตัวเอง
Edge Functionsที่รันโค้ด TypeScript ฝั่งเซิร์ฟเวอร์ (Deno)parse-slip และ coach ซึ่งถือกุญแจ AI (บท A10)
Dashboardหน้าเว็บจัดการทั้งหมดดูตาราง รัน SQL ตั้ง Secrets ดู log

โปรเจกต์ของทีมอยู่ภูมิภาค Singapore (ใกล้ไทย ตอบเร็ว) และใช้แพ็กเกจฟรี

แทนที่จะคลิกสร้างตารางในหน้าเว็บ ทีมเราเขียนคำสั่ง SQL ไว้ในไฟล์ เรียกว่า migration เรียงตามวันที่ในชื่อไฟล์ ใครจะสร้างฐานข้อมูลใหม่ก็แค่รันไฟล์ตามลำดับ ได้ฐานข้อมูลเหมือนกันทุกตัว และเก็บประวัติใน Git ได้

ตาราง ai_usage: นับการใช้ AI

ทุกครั้งที่ AI ถูกเรียก (อ่านสลิป 1 ใบ หรือถามโค้ช 1 ครั้ง) Edge Function จะเพิ่ม 1 แถว เพื่อนับว่าวันนี้ใช้ไปกี่ครั้งแล้ว กันบัญชีเดียวใช้ AI จนค่าใช้จ่ายบานปลาย (ผู้ใช้อ่านของตัวเองได้ แต่เขียนได้เฉพาะเซิร์ฟเวอร์)

Row Level Security (RLS): หัวใจความปลอดภัย

กุญแจสาธารณะ (publishable key) ในแอปเหมือน "บัตรเข้าห้องสมุด" ใครมีก็เดินเข้าห้องได้ แต่ละคนมีล็อกเกอร์ของตัวเอง RLS คือ "ยามประจำล็อกเกอร์" ที่ดูบัตรประชาชน (การเข้าสู่ระบบ) ทุกครั้ง และเปิดให้เฉพาะล็อกเกอร์ที่มีชื่อเรา แม้แฮกเกอร์จะขโมยบัตรเข้าห้องสมุด (กุญแจในแอป) ไปได้ ก็เปิดล็อกเกอร์คนอื่นไม่ได้
บรรทัดความหมาย
70–72เปิด RLS ทั้ง 3 ตาราง พอเปิดแล้ว ค่าเริ่มต้นคือ ห้ามทุกอย่าง ต้องมี policy อนุญาตทีละเรื่อง
74–76policy "own profile read": อ่านโปรไฟล์ได้ เฉพาะแถวที่ id ตรงกับคนที่เข้าสู่ระบบ (auth.uid() = id) drop policy if exists ด้านบนคือลบของเก่าก่อน ทำให้รันไฟล์ซ้ำได้
77–79แก้โปรไฟล์ได้เฉพาะของตัวเอง using = ตรวจแถวเดิม, with check = ตรวจแถวหลังแก้ (กันแก้ id ให้เป็นของคนอื่น) ไม่มี policy insert/delete เพราะโปรไฟล์สร้างโดย trigger เท่านั้น
81–83รายการเงิน: ทำได้ทุกอย่าง (for all = อ่าน เพิ่ม แก้ ลบ) เฉพาะแถวที่ user_id เป็นของตัวเอง
85–87ai_usage อ่านได้อย่างเดียวและเฉพาะของตัวเอง

ทีมทดสอบเรื่องนี้ด้วยแผน MT-10 "บัญชี A ไม่เห็นรายการของบัญชี B" และรันตัวตรวจ Security Advisor ของ Supabase แล้วแก้จนไม่เหลือคำเตือนเรื่องตาราง ไฟล์ harden.sql เปลี่ยน auth.uid() เป็น (select auth.uid()) เพื่อให้ฐานข้อมูลคำนวณครั้งเดียวต่อคำสั่ง แทนที่จะคำนวณทุกแถว (เร็วขึ้นเมื่อมีรายการเยอะ)
