Git: ระบบบันทึกประวัติ

Git เหมือนปุ่ม "Save game" ของเกม ทุกครั้งที่ทำสำเร็จหนึ่งด่าน (แก้ฟีเจอร์เสร็จ) เราเซฟไว้พร้อมโน้ตว่าทำอะไร ถ้าพลาดภายหลังก็โหลดเซฟเก่ากลับมาได้ และดูย้อนได้ว่าใครเปลี่ยนอะไรเมื่อไร
คำความหมาย
repository (repo)โฟลเดอร์โปรเจกต์ที่ Git ดูแล รวมประวัติทั้งหมด (ซ่อนอยู่ในโฟลเดอร์ .git)
commit"จุดเซฟ" 1 ครั้ง มีรหัส (เช่น 646b485) ข้อความอธิบาย ผู้ทำ และเวลา
branch"เส้นทางคู่ขนาน" ของโค้ด แยกไปทำฟีเจอร์โดยไม่กระทบเส้นหลัก เส้นหลักของทีมชื่อ main
remote / originสำเนาของ repo บนเซิร์ฟเวอร์ (GitHub)
pushส่ง commit ในเครื่องขึ้น GitHub
pullดึง commit ใหม่จาก GitHub ลงเครื่อง
cloneคัดลอก repo ทั้งหมดจาก GitHub ลงเครื่องครั้งแรก
pull request (PR)คำขอรวม branch หนึ่งเข้า main ให้เพื่อนรีวิวก่อน
merge conflictสองคนแก้บรรทัดเดียวกัน Git ไม่รู้จะเลือกของใคร ต้องตัดสินใจเอง
.gitignoreรายชื่อไฟล์ที่ไม่ต้องเก็บใน Git เช่น node_modules (ใหญ่และติดตั้งใหม่ได้), .env (อาจมีความลับ), dist (สร้างใหม่ได้)

ใช้ Git ประจำวัน

git pull # 1. ดึงของล่าสุดก่อนเริ่ม git checkout -b fix-runway-text # 2. แยก branch ใหม่ (ไม่บังคับ) # ... แก้โค้ดใน VS Code ... npm test # 3. รันเทสต์ให้ผ่านก่อน git status # 4. ดูว่าแก้ไฟล์ไหนไปบ้าง git add src/domain/runway.ts # 5. เลือกไฟล์ที่จะเซฟ git commit -m "Runway: say 'ประมาณ' in the date" # 6. เซฟพร้อมข้อความ git push -u origin fix-runway-text # 7. ส่งขึ้น GitHub แล้วเปิด Pull Request

ใน VS Code ทำแบบเดียวกันได้ด้วยเมาส์ที่แท็บ Source Control (Ctrl+Shift+G): ไฟล์ที่แก้จะขึ้นในรายการ กด + เพื่อเลือก พิมพ์ข้อความ กด Commit แล้วกด Sync Changes

บอกว่า "ทำอะไร และทำไม" สั้น ๆ เช่นของทีมเรา: "Runway: arrow keys on the web; steadier drag test", "Audit follow-up: fix regressions found by independent review" อ่านประวัติแล้วรู้เรื่องโดยไม่ต้องเปิดโค้ด ดูประวัติทั้งหมดด้วย git log --oneline

GitHub Actions: หุ่นยนต์ที่ทำงานทุกครั้งที่ push

CI/CD (Continuous Integration / Continuous Delivery) คือให้คอมพิวเตอร์ทดสอบและส่งของให้อัตโนมัติทุกครั้งที่โค้ดเปลี่ยน ของทีมเราเขียนเป็นไฟล์ YAML ใน .github/workflows/ มี 4 ตัว

ไฟล์ทำอะไรผลลัพธ์
web.ymlbuild เว็บ → unit test → E2E 145 ข้อ → ถ้าผ่านทั้งหมดจึงเผยแพร่เว็บที่ 2550expo-tech.github.io/Socrates-and-Skeletons-/
android-apk.ymlunit test → typecheck → สร้างโปรเจกต์ Android → build APK (15–25 นาที)ไฟล์ mind-pay.apk ในหน้า Releases "latest-apk"
eas-update.ymlunit test → ส่งโค้ด JavaScript ใหม่ขึ้น EAS Updateแอปที่ลงแล้วได้โค้ดใหม่ตอนเปิดครั้งถัดไป
e2e-webkit.ymlE2E ชุดเดียวกันบนเอนจิน Safari แบบ iPhone โหมดมืดรายงานผล (ไม่บล็อกการเผยแพร่)
git push ขึ้น main
↓ GitHub เปิดเครื่องเสมือน Ubuntu ให้ฟรีตัวละ 1 เครื่อง ทำพร้อมกัน
web.ymlเทสต์ไม่ผ่าน = เว็บไม่เปลี่ยน ผู้ใช้ยังได้เวอร์ชันเดิมที่ดีอยู่
android-apk.ymlเทสต์หรือ typecheck ไม่ผ่าน = ไม่มี APK ใหม่
eas-update.ymlต้องมี secret EXPO_TOKEN และเทสต์ผ่าน
e2e-webkit.ymlตรวจบน Safari เพิ่ม
