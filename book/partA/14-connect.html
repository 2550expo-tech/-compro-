คำถามระดับระบบ ที่อาจารย์ถามใครก็ได้

Q1ทำไมเลือก Expo / React Native?
โค้ดชุดเดียวได้ทั้ง Android, iPhone และเว็บ ทีมเล็กเวลาน้อยจึงไม่ต้องเขียน 3 รอบ ภาษาเดียว (TypeScript) ทั้งแอปและเซิร์ฟเวอร์ มีเครื่องมือ build APK และส่งอัปเดตอัตโนมัติ
Q2ทำไมเลือก Supabase?
ได้ฐานข้อมูล PostgreSQL, ระบบสมัคร/เข้าสู่ระบบ, และที่รันโค้ดฝั่งเซิร์ฟเวอร์ในที่เดียว มีแพ็กเกจฟรี และ Row Level Security ทำให้แอปคุยกับฐานข้อมูลได้ตรง ๆ อย่างปลอดภัยโดยไม่ต้องเขียนเซิร์ฟเวอร์ API เอง
Q3ข้อมูลผู้ใช้ปลอดภัยยังไง?
ทุกตารางเปิด RLS แต่ละคนอ่านเขียนได้เฉพาะแถวของตัวเอง (ทดสอบ MT-10) กุญแจในแอปเป็นกุญแจสาธารณะ กุญแจลับและกุญแจ AI อยู่บนเซิร์ฟเวอร์เท่านั้น รูปสลิปไม่ถูกเก็บบนเซิร์ฟเวอร์ โค้ชได้แค่ยอดรวม
Q4ทำไมเก็บเงินเป็นสตางค์?
ทศนิยมในคอมพิวเตอร์ไม่เป๊ะ (0.1 + 0.2 = 0.30000000000000004) เก็บเป็นจำนวนเต็มสตางค์จึงบวกลบได้แม่นยำ 100% แปลงเป็นบาทตอนแสดงผลเท่านั้น
Q5ทำไมต้องจัดวันตามเวลาไทย?
ฐานข้อมูลเก็บเวลา UTC ซึ่งช้ากว่าไทย 7 ชั่วโมง ถ้าไม่แปลง รายการตอนเช้ามืดจะไปอยู่วันก่อนหน้า ยอด "วันนี้" และค่าเฉลี่ย 7 วันจะผิด ทุกจุดจึงใช้ bkkDayKey
Q6ยอดคงเหลือเก็บไว้ในฐานข้อมูลไหม?
ไม่ เก็บเฉพาะรายการ ตัวเลขทั้งหมด (ยอด ค่าเฉลี่ย Runway) คำนวณสดในเครื่องจากรายการทุกครั้งที่ข้อมูลเปลี่ยน ตัวเลขจึงไม่มีทางขัดกันเอง
Q7แบบร่าง (draft) คืออะไร ทำไมต้องมี?
รายการจากสลิปที่ AI อ่านไม่มั่นใจ รอผู้ใช้ตรวจก่อน ยังไม่นับในยอดใด ๆ เพราะถ้า AI อ่านผิดแล้วนับทันที ทุกตัวเลขในแอปจะผิดตาม
Q8ใช้ AI ตรงไหน และป้องกัน AI ผิดยังไง?
2 ที่: อ่านสลิป (FR-4) และโค้ช (FR-5) ป้องกันด้วย: อ่าน 2 ครั้งด้วย 2 รุ่น, เกณฑ์ความมั่นใจ 80%, ตรวจกับ QR บนสลิป, แบบร่างรอตรวจ, โค้ชห้ามแต่งตัวเลข ตัวเลขทั้งหมดคำนวณโดยโค้ดที่ทดสอบแล้ว
Q9ทำไมไม่เรียก AI จากแอปตรง ๆ?
กุญแจ AI จะหลุดไปกับแอป Edge Function ถือกุญแจไว้ ตรวจว่าเข้าสู่ระบบจริง และจำกัดโควตาต่อวันต่อคน
Q10ทดสอบยังไง?
3 ระดับ: unit test 157 ข้อ (ฟังก์ชันคำนวณ), E2E 145 ข้อ (เปิดเว็บจริงกดเหมือนคน ด้วยเซิร์ฟเวอร์ปลอม), manual test MT-01 ถึง MT-12 บนมือถือจริง ทุกครั้งที่ push GitHub รันเทสต์ก่อนเผยแพร่
Q11ถ้าอินเทอร์เน็ตหลุดระหว่างพรีเซนต์?
ใช้โหมดทดลอง ข้อมูลอยู่ในเครื่อง ทำงานได้ทุกอย่างยกเว้น AI
Q12Requirement โยงกับโค้ดยังไง?
เอกสาร docs/TRACEABILITY.md ผูกทุก acceptance criteria ของทุก FR กับไฟล์/ฟังก์ชันที่ทำ และรหัสเทสต์ (TC/MT) ที่พิสูจน์
Q13ใช้ AI ช่วยเขียนโค้ดไหม?
ใช้ บันทึกไว้ใน docs/AI_USAGE_LOG.md ตามที่ SRS กำหนด ทุกแถวบอกจุดประสงค์ ผลลัพธ์ สิ่งที่ทีมแก้หรือตัดสินใจ และสิ่งที่สมาชิกต้องตรวจเอง (ควรตอบตามจริงว่าตัวเองตรวจอะไรไปแล้วบ้าง)
Q14ถ้ามีผู้ใช้เยอะขึ้น ระบบรับไหวไหม?
การคำนวณทำในเครื่องของแต่ละคน เซิร์ฟเวอร์แค่เก็บข้อมูล มี index ช่วยค้นเร็ว และโหลดเป็นหน้า หน้าละ 1,000 แถว ส่วนที่ต้องระวังคือค่าใช้จ่าย AI ซึ่งมีโควตาต่อวันคุมไว้ และควรเปลี่ยนจาก Gemini แบบฟรีเป็นแบบเสียเงินเมื่อมีผู้ใช้จริง
Q15อะไรที่ยังไม่ได้ทำ (นอก MVP)?
Accountability Mode (UC-7), ออฟไลน์เต็มระบบ (UC-8), เชื่อม Gmail/LINE, รวมรายรับในอนาคตเข้า Money Runway และยังไม่ได้ทดสอบบนมือถือหลายรุ่น
