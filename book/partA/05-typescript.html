ทำไมต้อง TypeScript

ใน JavaScript ธรรมดา ถ้าพิมพ์ tx.amountSatnag (สะกดผิด) โปรแกรมจะรันได้ แต่ได้ค่า undefined แล้วยอดเงินเพี้ยนตอนผู้ใช้กำลังใช้ ส่วน TypeScript จะขีดเส้นแดงใน VS Code ทันทีว่า "ไม่มีช่องชื่อนี้" ทีมเราเปิดโหมดเข้มงวดที่สุด ("strict": true ในไฟล์ tsconfig.json) และรัน npm run typecheck ก่อน build APK ทุกครั้ง

TypeScript เหมือนแบบฟอร์มราชการที่มีช่องบังคับว่า "ช่องนี้ต้องเป็นตัวเลข 13 หลัก" กรอกผิดเจ้าหน้าที่ตีกลับทันทีที่โต๊ะ ดีกว่าไปรู้ตอนเอกสารเข้าระบบแล้ว เมื่อ build แอป ชนิดข้อมูลทั้งหมดจะถูกลบออก เหลือ JavaScript ธรรมดา ชนิดข้อมูลจึงช่วยเราตอนเขียนโค้ดเท่านั้น ไม่ทำให้แอปช้าลง

การบอกชนิดข้อมูล (type annotation)

const days: number = 16; const title: string = 'ข้าวมันไก่'; let slipRef: string | null = null; // เป็น string หรือ null ก็ได้ function toBaht(satang: number): number { return satang / 100; }

หลายครั้งไม่ต้องเขียนชนิดเอง TypeScript เดาเองได้ (type inference) เช่น const days = 16 รู้เองว่าเป็น number เอาเมาส์ชี้ใน VS Code จะเห็นชนิดที่มันเดา

งานที่ต้องรอ: async, await และ Promise

การคุยกับอินเทอร์เน็ตใช้เวลา (อาจครึ่งวินาทีหรือหลายวินาที) ถ้าแอปหยุดรอเฉย ๆ หน้าจอจะค้าง JavaScript จึงใช้ Promise คือ "ใบรับของ" ที่บอกว่าเดี๋ยวผลจะมา

async function save() { // async = ฟังก์ชันนี้มีงานที่ต้องรอ const tx = await repo.insert(input); // await = รอตรงนี้จนได้ผล แต่หน้าจอไม่ค้าง setTxs((list) => [tx, ...list]); // ทำต่อเมื่อได้ผลแล้ว }

ถ้ามีหลายงานที่ไม่ต้องรอกัน ใช้ Promise.all ทำพร้อมกัน เช่น ตอนโหลดข้อมูลครั้งแรก แอปโหลดโปรไฟล์ รายการ และกระปุกออม พร้อมกันทั้ง 3 อย่าง

บรรทัด 133: เรียก 3 งานพร้อมกัน แล้วรอจนเสร็จทั้งหมด ผลออกมาเป็น array 3 ช่อง แกะใส่ตัวแปร p, list, g ส่วน .catch(() => []) ท้ายงานที่ 3 แปลว่า "ถ้าโหลดกระปุกออมไม่ได้ ให้ถือว่าไม่มีกระปุก" แอปส่วนอื่นยังใช้ได้ (Supabase ฝั่งเซิร์ฟเวอร์ ใน Edge Function ก็ใช้ Promise.allSettled อ่านสลิป 2 ครั้งพร้อมกันแบบเดียวกัน บท A10)

จัดการความผิดพลาด: try, catch, throw

try { await addTx(input); // ลองทำ toast({ message: 'บันทึกรายการแล้ว' }); } catch (e) { // ถ้ามี error ระหว่างทาง กระโดดมาที่นี่ toast({ message: 'บันทึกไม่สำเร็จ ลองอีกครั้ง', tone: 'error' }); } finally { // ทำเสมอ ไม่ว่าสำเร็จหรือพลาด setBusy(false); }

class ... extends Error = สร้างชนิด error ใหม่โดยต่อยอดจาก Error ธรรมดา super(...) ส่งข้อความภาษาไทยให้ Error ตัวแม่ และตั้ง name ไว้ให้หน้าจอเช็กได้ว่าเป็น error แบบไหน (ดู src/app/transaction.tsx:126)

ทำไมเก็บเงินเป็นสตางค์ (จำนวนเต็ม)

คอมพิวเตอร์เก็บทศนิยมเป็นเลขฐานสอง ซึ่งเก็บบางค่าได้ไม่เป๊ะ ทดลองรันใน Node.js จริง:

0.1 + 0.2      → 0.30000000000000004
19.99 * 100    → 1998.9999999999998

ถ้าบวกเงินเป็นบาททศนิยมหลายพันรายการ เศษเล็ก ๆ จะสะสมจนยอดเพี้ยน ทางแก้คือเก็บเป็น สตางค์ (จำนวนเต็ม) ทั้งหมด เช่น ฿85.50 เก็บเป็น 8550 จำนวนเต็มบวกลบกันได้แม่นยำ 100% แล้วค่อยแปลงเป็นบาทตอนแสดงบนจอ ฐานข้อมูลก็เก็บเป็นจำนวนเต็ม (คอลัมน์ amount_satang bigint)

อ่านโค้ดจริง: แปลงข้อความที่ผู้ใช้พิมพ์เป็นสตางค์

ฟังก์ชัน parseBahtToSatang ใน src/domain/money.ts ใช้ทุกที่ที่ผู้ใช้กรอกจำนวนเงิน (FR-1 จดรายการ, ตั้งค่า, เช็กก่อนจ่ายของ FR-6, กระปุกออม) และใช้กับยอดเงินที่ AI อ่านจากสลิปด้วย

ตัวอย่าง /^\d{1,3}(,\d{3})+(\.\d{1,2})?$/ อ่านว่า: "ขึ้นต้นด้วยตัวเลข 1–3 หลัก ตามด้วย (คอมมา + ตัวเลข 3 หลัก) อย่างน้อย 1 ชุด แล้วอาจมี (จุด + ตัวเลข 1–2 หลัก) และจบข้อความ" ซึ่งก็คือรูปแบบ 1,234 หรือ 12,345,678.50
