MindPay ไม่ได้ แปลงเสียงเอง เราขอให้ "ล่าม" ที่มากับเครื่องทำ: Android ใช้บริการของ Google, iPhone ใช้ของ Apple, เว็บใช้ของเบราว์เซอร์ (Chrome/Edge/Safari) ไฟล์นี้คือ "คนประสานงานกับล่าม" บอกว่าฟังภาษาไทย ช่วยด้วยคำศัพท์เรื่องเงิน และส่งข้อความกลับมาให้หน้าจอ

ส่วนที่ 1: หาโมดูลแบบไม่บังคับ (บรรทัด 1–33)

บรรทัดความหมาย
1–3คอมเมนต์: แปลงเสียงเป็นข้อความบนมือถือ ภาษาไทย ด้วยตัวแปลงของระบบ (Google บน Android, Apple บน iOS) ผ่าน expo-speech-recognition
5–8เหตุผลสำคัญ: โมดูลถูกหา "แบบไม่บังคับ" เพราะแอปที่ build ก่อนเพิ่มโมดูลนี้ไม่มีมัน และการอัปเดตแบบ over-the-air (EAS Update ส่งแต่โค้ด JavaScript) ต้องไม่ทำให้แอปเหล่านั้นพัง — ในเครื่องแบบนั้นหน้าพูดจดจะเสนอให้พิมพ์แทน · เวอร์ชันเว็บอยู่ใน speech.web.ts
10requireOptionalNativeModule จาก expo: หาโมดูลเนทีฟ ถ้าไม่มี คืน null (ไม่โยนข้อผิด)
12–14ชนิด Subscription: สิ่งที่ได้จากการสมัครฟังเหตุการณ์ มีคำสั่ง remove() ยกเลิก
15–22ชนิด NativeSpeech = คำสั่งที่โมดูลเนทีฟมี: เริ่ม, หยุด, ยกเลิก, ขอสิทธิ์ (ได้ granted และถามซ้ำได้ไหม), มีตัวแปลงไหม, ฟังเหตุการณ์
24Speech = โมดูลชื่อ 'ExpoSpeechRecognition' หรือ null
26–33ListenHandlers สัญญาที่หน้าจอส่งมา: onText (ข้อความที่ได้ยินถึงตอนนี้ และจบประโยคหรือยัง), onError (รหัสข้อผิด), onEnd (ฟังจบ), onVolume (ความดัง 0–1 สำหรับแอนิเมชัน ไม่บังคับ)

ส่วนที่ 2: คำช่วย มีตัวฟังไหม และขอสิทธิ์ (บรรทัด 35–55)

บรรทัดความหมาย
35–36HINTS คำที่ช่วยตัวแปลงเสียงฟังเรื่องเงินแม่นขึ้น: บาท ค่ารถ ค่าข้าว ข้าว กาแฟ ชานม ค่าหอ ค่าเน็ต เงินเดือน ได้เงินจากแม่ เซเว่น
38–44speechAvailable: มีโมดูล และระบบบอกว่ามีบริการแปลงเสียง ถ้าเกิดข้อผิดใด ๆ ตอบ false (ปลอดภัยไว้ก่อน)
46–47askMicPermission: ไม่มีโมดูล → denied
48–50ขอสิทธิ์ (ระบบแสดงหน้าต่างถามผู้ใช้) ได้ → 'granted'
51ไม่ได้: ถ้าระบบบอกว่า "ถามซ้ำไม่ได้แล้ว" (ผู้ใช้เลือกไม่ต้องถามอีก) → 'blocked' (ต้องไปเปิดในการตั้งค่า) ไม่งั้น 'denied'
52–54ข้อผิด → denied

ส่วนที่ 3: listen — เริ่มฟัง (บรรทัด 57–96)

บรรทัดความหมาย
57–58เริ่มฟัง คืนฟังก์ชันสำหรับหยุด (ข้อความที่ได้ยินแล้วเก็บไว้)
59–62ไม่มีโมดูล → แจ้งข้อผิด 'unavailable' คืนฟังก์ชันว่าง
63–64รายการการสมัครฟังเหตุการณ์ และ done() = ยกเลิกทั้งหมด (splice(0) เอาออกทั้งหมดแล้ววน remove)
65–68เหตุการณ์ result: เอาข้อความของผลลัพธ์แรก ส่งให้ onText พร้อมบอกว่าจบประโยคหรือยัง
69เหตุการณ์ error: ส่งรหัส (ไม่มี = 'unknown')
70เหตุการณ์ volumechange: ระบบให้ค่าประมาณ −2 ถึง 10 แปลงเป็น 0–1 ด้วย (ค่า + 2) ÷ 12 และบีบให้อยู่ระหว่าง 0–1
71–74เหตุการณ์ end: ยกเลิกการฟังเหตุการณ์ทั้งหมด แล้วแจ้ง onEnd
76–84เริ่มฟัง: ภาษา th-TH, ส่งผลระหว่างพูด (interim) ด้วย, ฟังประโยคเดียวแล้วหยุดเอง (continuous: false), ขอคำตอบแบบเดียว, คำช่วย HINTS, ส่งความดังทุก 120 มิลลิวินาที
85–88เริ่มไม่ได้ → ยกเลิกและแจ้ง 'unavailable'
89–95ฟังก์ชันหยุดที่คืนไป: สั่ง stop (ถ้าหยุดไปแล้วก็ไม่เป็นไร)
บรรทัดความหมาย
1–5คอมเมนต์: Web Speech API ภาษาไทย (Chrome และ Edge บนคอม/Android; Safari บน iPhone ขอใช้ไมค์และใช้ตัวแปลงของ Siri) เบราว์เซอร์ที่ไม่มีก็พิมพ์แทน
6ใช้ชนิด ListenHandlers จากไฟล์มือถือ (สัญญาเดียวกัน)
8–18ชนิด Recognition = หน้าตาของวัตถุฟังเสียงของเบราว์เซอร์: ภาษา, ผลระหว่างพูด, ฟังต่อเนื่อง, จำนวนคำตอบ, ตัวรับผล/ข้อผิด/จบ, เริ่ม/หยุด
20–24Ctor = ตัวสร้างของเบราว์เซอร์: ถ้าไม่มี window (ตอนสร้างหน้าเว็บล่วงหน้า) → undefined ไม่งั้นใช้ SpeechRecognition หรือ webkitSpeechRecognition (ชื่อเก่าของ Chrome/Safari)
26ส่งชนิดต่อให้ไฟล์อื่นใช้
28–30มีตัวสร้าง = ฟังได้
32–35บนเว็บ เบราว์เซอร์ขอสิทธิ์ไมค์เองตอนเริ่มฟัง จึงตอบ granted ถ้ามีตัวสร้าง
บรรทัดความหมาย
37–41ไม่มีตัวสร้าง → unavailable
42–46สร้างตัวฟัง ตั้งภาษาไทย ผลระหว่างพูด ประโยคเดียว คำตอบเดียว
47–55ได้ผล: ต่อข้อความทุกช่วงเข้าด้วยกัน (เบราว์เซอร์อาจแบ่งเป็นหลายช่วง) ถ้ามีช่วงไหนยังไม่จบ final = false แล้วส่ง onText
56ข้อผิด: รวม not-allowed และ service-not-allowed เป็น 'not-allowed' (ข้อความเดียวกัน) ที่เหลือส่งรหัสตรง ๆ
57จบ → onEnd
58–62เริ่ม ถ้าพัง → unavailable
63–69ฟังก์ชันหยุด

หน้าจอเขียน import ... from '../services/speech' ไม่มี .web ตอน build เว็บ เครื่องมือ (Metro) จะหาไฟล์ speech.web.ts ก่อน ตอน build แอปจะใช้ speech.ts (บท A7) สองไฟล์จึงต้อง export ชื่อเดียวกัน (speechAvailable, askMicPermission, listen) และส่งข้อมูลรูปแบบเดียวกัน

เทสต์ใส่ "ตัวฟังเสียงจำลอง" (FakeRecognition) แทน webkitSpeechRecognition ก่อนเปิดหน้า: เมื่อ start() มันจำภาษาที่ตั้งไว้ ส่ง "ข้าวมันไก่" (ยังไม่จบ) ที่ 0.3 วินาที และ "ข้าวมันไก่ 50 บาท" (จบ) ที่ 0.9 วินาที แล้วจบ เทสต์จึงตรวจได้ทั้งว่า speech.web.ts ตั้งภาษา th-TH และหน้าจอได้รายการ ฿50 (e2e/web-auth.mjs:826)
บรรทัดความหมาย
71–72ใช้ปลั๊กอิน expo-speech-recognition (ตอน build แอปจะใส่โค้ดเนทีฟและสิทธิ์ให้)
74ข้อความที่ระบบแสดงตอนขอใช้ไมโครโฟน: "MindPay ใช้ไมโครโฟนเมื่อคุณแตะปุ่มไมค์เพื่อพูดจดรายการ เช่น “ข้าว 50 บาท”" (บอกเหตุผลชัดเจน ผู้ใช้จะกล้ากดอนุญาต)
75ข้อความขอใช้การแปลงเสียง (iOS): "MindPay แปลงเสียงที่คุณพูดเป็นรายการรายรับรายจ่าย"
76–78Android: ระบุแพ็กเกจบริการแปลงเสียงของ Google
