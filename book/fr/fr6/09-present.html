3แตะแท็บ "เงินพอถึง" (ไอคอนใบไม้) เลื่อนลงที่การ์ด "คำนวณยังไง"อ่านตัวเลขบนจอ แล้วกดเครื่องคิดเลขในมือถือให้ดู: ใช้ได้จริง ÷ ค่าเฉลี่ย แล้วปัดลง "ได้เท่ากับเลขใหญ่ข้างบน"

7(ถ้ามีเวลา) กด "ถามโค้ชเรื่องนี้""คำถามพร้อมราคาถูกส่งไปรอที่หน้าโค้ชแล้ว แอปคิดตัวเลขก่อน ส่งให้ AI แค่อธิบาย"
8(ถ้ามีเวลา) หน้าหลัก → ไอคอนเฟือง "ตั้งค่า" มุมขวาบน → ใส่เงินสำรองสูง ๆ → กด "บันทึก" → กลับไปดูหน้าเงินพอถึง"สถานะเปลี่ยนทันที เพราะคิดใหม่ทุกครั้งที่ข้อมูลเปลี่ยน" แล้ว ตั้งกลับเป็น 500

ตัวเลขไม่เท่าสไลด์: ข้อมูลตัวอย่างถูกสร้างตามวันที่กด "ลองใช้ด้วยข้อมูลตัวอย่าง" ครั้งแรก จึงต่างจากภาพในสไลด์ (ถ่ายวันที่ 9 ต.ค.) ไม่ต้องจำตัวเลข อ่านจากจอแล้วคิดด้วยสูตรเดิม เทสต์ TC-33 รับประกันว่าข้อมูลที่สร้างวันไหนก็ตาม มี Runway อย่างน้อย 10 วัน หน้าจอจะไม่แดงตอนเดโม

สร้างข้อมูลตัวอย่างใหม่ในวันนำเสนอ: ข้อมูลตัวอย่างถูกเก็บไว้ในเครื่องหลังสร้างครั้งแรก ถ้าซ้อมด้วยเบราว์เซอร์เดียวกันไว้หลายวันก่อน รายการจะเก่า ค่าเฉลี่ย 7 วันอาจเหลือน้อยจนตัวเลขแปลก ก่อนเดโมให้ไปที่ ตั้งค่า → "ออกจากโหมดทดลอง" แล้วกด "ลองใช้ด้วยข้อมูลตัวอย่าง" ใหม่ (หรือเปิดหน้าต่างแบบไม่ระบุตัวตน) แอปจะสร้างข้อมูลชุดใหม่ของวันนั้น

โค้ชในโหมดทดลองตอบไม่ได้: ถ้ากดส่งคำถามในหน้าโค้ช แอปจะตอบว่า "โหมดทดลองยังถาม AI ไม่ได้นะ เข้าสู่ระบบด้วยบัญชีจริง…" เพราะ AI ทำงานผ่านเซิร์ฟเวอร์ที่ต้องเข้าสู่ระบบ ถ้าอยากโชว์คำตอบของ AI ต้องเดโมด้วยบัญชีจริงที่มีรายการแล้ว ไม่งั้นหยุดที่ข้อ 7 (คำถามไปรอในช่องพิมพ์) ก็พอ

ขยายจอ: บนเว็บกด Ctrl กับ + ให้ตัวหนังสือใหญ่ขึ้น คนหลังห้องจะเห็นตัวเลข

แผนสำรองเมื่อเกิดเรื่องไม่คาดคิด

อินเทอร์เน็ตล่ม เปิดสไลด์หรือเว็บไม่ได้เปิดไฟล์ PDF หรือ PowerPoint ที่ดาวน์โหลดไว้ สไลด์ 12–18 เป็นภาพหน้าจอจริงทั้งหมด ใช้แทนเดโมได้เลย
อาจารย์ขอดูโค้ดจริงเปิดลิงก์ "เปิดใน VS Code (เว็บ)" ใต้โค้ด runway.ts ในบท "อ่านโค้ด: runway.ts ทั้งไฟล์" หรือเปิด GitHub แล้วไปที่ src/domain/runway.ts บรรทัด 72–94
อาจารย์ขอให้รันเทสต์ให้ดูเปิด Terminal ในโฟลเดอร์โปรเจกต์ พิมพ์ npm test รอไม่กี่วินาที ชี้บรรทัด Tests 157 passed (157) (ต้องเตรียมเครื่องตามขั้นที่ 0 ในบท "สร้าง FR-6 ตั้งแต่ศูนย์" ไว้ก่อน)
ตื่นเต้นจนลืมว่าจะพูดอะไรดูคอลัมน์ "ต้องพูดให้ได้" ในตารางข้างบน หรือข้ามไปสไลด์ 25 แล้วพูด 3 ประโยคสรุป
เวลาหมดก่อนจบกระโดดไปสไลด์ 25 ทันที พูด 3 ประโยค แล้วจบ ดีกว่าพูดเร็วจนไม่มีใครฟังทัน
โดนถามเรื่องที่ไม่รู้คำตอบพูดตรง ๆ ว่า "ขอตรวจในโค้ดก่อนแล้วจะตอบภายหลัง" ห้ามเดา อาจารย์ให้คะแนนความซื่อตรงมากกว่าคำตอบที่มั่ว

ตอบใน 1 ประโยค (ท่องให้คล่อง)

คำตอบเต็มอยู่ในบท "คำถามที่อาจารย์อาจถาม พร้อมคำตอบ" ส่วนนี้คือฉบับย่อสำหรับตอบทันที

1ทำไม 7 วัน? ครบรอบสัปดาห์ ตามนิสัยล่าสุดทัน และตรงกับ SRS
2ทำไมปัดลง? บอกน้อยไว้ปลอดภัยกว่า วันที่ปัดขึ้นไปเงินจะต่ำกว่าเส้นแล้ว
3ไม่มีรายจ่ายเลย? ไม่หารด้วยศูนย์ แสดง "ยังคำนวณไม่ได้" (TC-15)
4ผู้ใช้ใหม่? หารด้วยจำนวนวันที่ใช้แอปมาจริง ไม่เกิน 7 (TC-13)
5เงินต่ำคืออะไร? ยอด ≤ เส้นสำรองที่ตั้งเอง ค่าเริ่มต้น ฿500 (TC-16)
6สลิปที่ยังไม่ยืนยัน? ไม่นับ จนกว่าผู้ใช้กดยืนยัน เพราะ AI อาจอ่านผิด
7เก็บ Runway ในฐานข้อมูลไหม? ไม่ คิดสดในเครื่องทุกครั้ง ตัวเลขจึงไม่ค้าง
8AI คิด Runway เองไหม? ไม่ โค้ดที่ผ่านเทสต์คิด AI แค่อธิบายเป็นภาษาคน
9รายรับในอนาคต? ยังไม่นับ เป็นข้อจำกัดที่เขียนบอกไว้บนจอ และอยู่ในแผนต่อไป
10ซื้อของแพงครั้งเดียว? ค่าเฉลี่ยสูงชั่วคราว 7 วันแล้วกลับปกติ แก้ได้ด้วยค่ามัธยฐาน
11ทำไมเก็บเป็นสตางค์? จำนวนเต็มไม่เพี้ยน 0.1 + 0.2 ในคอมพิวเตอร์ไม่ได้ 0.3 พอดี
12พิสูจน์ว่าถูกยังไง? unit test TC-12–18 ที่ขอบเกณฑ์ + E2E ในเบราว์เซอร์ + ผู้ใช้ตรวจเองได้จากการ์ด "คำนวณยังไง"
13กระบวนการพัฒนา? นิยามที่ทดสอบได้ → เทสต์ → pure function → useMoney → หน้าจอ → E2E → ปรับตาม feedback (บท "สร้าง FR-6 ตั้งแต่ศูนย์")

เทคนิคการพูดที่ช่วยได้จริง

  • ใช้ตัวอย่างเดียวตลอด ฿3,500 สำรอง ฿500 ใช้วันละ ฿145 ได้ 20 วัน ผู้ฟังจำได้ ไม่ต้องคิดตัวเลขใหม่ทุกหน้า
  • พูดตัวเลขช้าลงครึ่งหนึ่ง และชี้ไปที่ตัวเลขบนจอทุกครั้งที่พูดถึง

  • บอกข้อจำกัดเองก่อนโดนถาม แสดงว่าเข้าใจระบบจริง (สไลด์ 24)
